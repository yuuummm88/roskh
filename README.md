# ROS CAMBO iOS launcher shell

A native SwiftUI iPhone/iPad project that recreates a launcher-style home screen, local server-profile selection, settings, connection status, and setup/error states. It is deliberately a **launcher shell**, not a Rules of Survival game client.

## Compatibility and safety boundary

The available Windows package contains a Windows game executable, Windows DLLs, packed game assets, process-specific client hooks, and a custom local replacement backend. None of these are used or copied into this iOS project. iOS cannot run those Windows binaries, and this project does not inject into or launch them.

The inspected package does not establish availability of an authorized iOS game client, supported public APIs, a compatible authentication flow, or a supported server protocol for a new iOS client. The local backend documentation describes custom game-specific UDP/TCP protocols; that is not an iOS API contract. Consequently:

- No login, game launch, server health check, or network request is implemented.
- Saved server profiles only store a display name and an HTTPS base URL. The app does not assume a route, protocol, credentials, or service compatibility.
- Pressing **Check connection setup** reports the missing integration and sends no request.
- The Keychain adapter is source-only groundwork for a future documented sign-in flow; no credential is collected or stored by this app yet.
- App artwork is original text/geometry generated by this project. No game artwork or assets from the Windows package are included; use game branding only with appropriate authorization.

Before adding connectivity, obtain written authorization plus the supported iOS client or SDK, HTTPS API contract, authentication specification, and compatible server deployment details. Implement only those documented contracts, enforce TLS, and store issued secrets in the iOS Keychain.

## Project contents

- `ROSCAMBO.xcodeproj` — native Xcode app target, iOS 17.0 minimum, iPhone and iPad, automatic signing setting, and placeholder bundle identifier.
- `Sources/` — SwiftUI views, profile/state models, view model, safe unconfigured service adapter, and Keychain storage helper.
- `Assets.xcassets/` — AppIcon asset catalog configuration.
- `Scripts/generate_app_icon.swift` — creates the project's original 1024×1024 icon using macOS AppKit.
- `Info.plist` — orientation and launch metadata.

## Build on GitHub from Windows and download the IPA

The included `.github/workflows/build-unsigned-ipa.yml` runs on a GitHub-hosted `macos-15` runner, selects Xcode 16.4, builds the `ROSCAMBO` target for generic iOS in Release with code signing disabled, creates an IPA with `Payload/ROSCAMBO.app`, verifies the archive and app executable, and uploads it as a workflow artifact. It needs no Apple account or signing secrets. **No IPA is created until you push the project and successfully run the workflow.**

1. On GitHub, create a new empty repository for this iOS project. Do not upload the Windows game bundle or the parent `cambo` folder; use only the contents of `ROSCAMBO-iOS`.
2. On Windows, clone that empty repository with GitHub Desktop (or Git), then copy all files and folders from `ROSCAMBO-iOS` into the cloned repository root. Include the hidden `.github` folder; it must be at the repository root as `.github/workflows/build-unsigned-ipa.yml` for GitHub to discover the workflow.
3. Commit and push the project files to GitHub. Do not add Apple certificates, private keys, provisioning profiles, or passwords; this unsigned workflow does not use them.
4. On GitHub, open the repository's **Actions** tab, select **Build unsigned iOS IPA**, choose **Run workflow**, then **Run workflow** again to confirm.
5. Wait for the run to complete successfully. Open that run, download the `ROSCAMBO-unsigned-IPA` artifact, and extract the downloaded artifact archive. Inside it is `ROSCAMBO-unsigned.ipa`.
6. Import the IPA into eSign and sign it there. Installation depends on a signing certificate and provisioning profile compatible with the app's bundle ID, the target device, and eSign's supported install method. The unsigned artifact is not automatically installable.

GitHub-hosted macOS runners and workflow artifacts are subject to GitHub account, usage, and retention limits. The artifact is configured to expire after seven days; download it before then. If the job fails, open the Actions run log and check the failing step; the workflow does not upload an IPA unless the build and package verification steps succeed.

### Optional local Mac build

On macOS with Xcode 16.4 or later, generate the original icon and build without signing:

```sh
swift Scripts/generate_app_icon.swift
xcodebuild -resolvePackageDependencies -project ROSCAMBO.xcodeproj -scheme ROSCAMBO
xcodebuild -project ROSCAMBO.xcodeproj -scheme ROSCAMBO -destination 'generic/platform=iOS' -configuration Release -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY='' build
```

This local build produces an `.app`; use the GitHub workflow for the verified unsigned IPA package. A signed Xcode archive instead requires macOS, Xcode, and valid Apple signing/provisioning credentials. App Store submission and game-service compatibility are separate requirements.

## Configuration notes

- Bundle identifier currently uses `com.example.roscambo.ios`; change it before distribution.
- No Apple Team ID or provisioning profile is committed.
- The app uses the platform's default App Transport Security behavior and only accepts HTTPS profile URLs. There is intentionally no request implementation until a real API contract is supplied.
- Profiles are stored locally in `UserDefaults` and contain no credentials.
- The Keychain helper uses `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` and is not connected to a speculative login flow.
